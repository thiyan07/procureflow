## SMART FEATURES (Rule-based + Lightweight)

- **Scheduler:** `scheduling_service.py` 10 rules (full reject, hours, occupancy `booked/capacity`, qty factor `1+(q-10)*0.02`, capacity `load/counters`, counters, safety buffer penalty, duplicate, past, DB `FOR UPDATE`). Score `availability*congestion*load*time*buffer`, tie `start_time,id`, `recommended_slot, wait, reason "Lower expected centre load.", alternatives×3`. Handles `counters=0 fallback 1`.
- **Waiting Intelligence:** `calculate_wait(farmers_ahead, avg, counters)` ceil, displayed everywhere, threshold `ahead <=2` triggers `turn_approaching` notification once per booking.
- **Demand/Centre Load:** `GET /ai/centre-load/{centre_id}?target_date=` 7-day bookings linear trend `m*idx+c+occupancy*5+queue*0.1`, levels `LOW <18 NORMAL <28 HIGH`, forecast 3d, `POST /analytics/management` demand trend + peak periods. Analytics screen bar chart 6 slots predicted, centre utilization gauge with `occupancy>85% red`.
- **Operator Queue Intelligence:** `GET /queue/centre/{centre_id}` list with farmer name, commodity `commodity_name` multi, qty total, status; `POST /queue/dev/advance` or `POST /queue/{bid}/transition` `WAITING→CALLED→ARRIVED→PROCESSING→COMPLETED/NO_SHOW/ON_HOLD/CANCELLED` + `QueueEvent`, `audit farmer_no_show/queue_on_hold/queue_completed/queue_cancelled` + notification for `NO_SHOW`. Estimate via `calculate_wait`.
- **Centre Capacity:** `GET /centres/{id}/capacity` `{total,used,remaining,occupancy,current_queue,active_counters,warnings[]}` warnings rule `>85% approaching, >95% almost full, queue>15, counters<2`; planner shows `Total Used Remaining + warnings`, analytics `Capacity` card `LinearProgress occ`.
- **Congestion Alerts (Rule-based, not ML):** `GET /centres/{id}/alerts` thresholds `queue>15 high, wait>30 medium, capacity>80% medium, counters<2 high, booking spike >50% avg 7d low` + deterministic `booking_spike: today vs avg7`; analytics `Congestion Alerts` AppCard with `severity high/medium/low` + `action` + info `Not ML`; operator dashboard `alerts` via same.

## AI FEATURES (Classical, Lightweight, Fallback)

- **Waiting-Time Prediction:** `waiting_time_service.py` Linear Regression `numpy.lstsq` 800 synthetic rows R2~0.85, `y=b0+farmers+avg+qty+load+hour`, fallback `calculate_wait`, `GET /ai/predict-wait?...` returns `predicted_wait, rule_wait, used_ai, reason, model_info`. Slot-recommendation-ai pipeline `VALID→RULE→AI WAIT→LOAD→RECOMMEND`. Never breaks booking, no large model, <10ms, only `numpy`.
- **Centre Load Prediction:** `centre_load_service.py` linear trend 7-day, `GET /ai/centre-load/{id}`.
- **Demand Forecasting:** `GET /ai/demand-forecast?centre_id&commodity&days=7` per centre/commodity/date 4-week weekday avg `hist same weekday past 4 weeks`, fallback `baseline 18` `confidence low` clearly marked if `avg<5`, else `medium`, returns `[{date,predicted_bookings,reason,confidence,historical_avg}]`, `model_info 4-week weekday avg fallback baseline 18`. Analytics `Demand Forecast (per centre, 7 days)` `LinearProgress /30` + `fallback` tag.
- **Anomaly Detection (Lightweight, not ML):** `GET /ai/anomalies/{centre_id}` rule-based `booking_spike today>avg7*1.8 high, queue>20 high, capacity>90% medium, processing delay >10min medium` + `normal` info else; no heavy model, uses `QueueToken`, `Booking`, `Slot`, `QueueEvent`; analytics `Anomaly Detection` `bug_report` icon + `reason`.
- **Assistant:** `assistant_service.py` deterministic FAQ en/ta/hi + DB context retrieval `token, slot, farmersAhead, wait, payment_status, amount, proc_stage`, Never hallucinates account data. `POST /assistant/ask?query&language_code` returns `answer, context_used`. Flutter chips `Where is my token?`.
- **Explainability:** Every `predicted_wait` returns `reason "AI predicts 6 min (rule 5) based on 5 ahead, 3 counters, qty 10q"` + large qty suffix, `centre_load reason "LOW load — approx X bookings expected (trend slope m)"`, `slot reason "Lower expected centre load"` never unexplained.
